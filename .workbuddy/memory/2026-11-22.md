- `.gitignore` 加 `*.pdf`（覆盖 `_build/study_pdf/` 那 4 份 doc→pdf），并用
  `git filter-branch --index-filter 'git rm -r --cached --ignore-unmatch _build/study_pdf' --prune-empty --tag-name-filter cat -- --all`
  从历史里清掉，再 `reflog expire + gc --prune=now`；结果：历史中 PDF 对象 0 个，`.git` 11MB→6.5MB，297 文件，最大对象 7.8MB。
- **⚠️ 事故与教训（重要）**：filter-branch 之后 `_build/` 整个目录从磁盘消失（含 814MB 工具链）。
  - 已恢复：31 个**被跟踪**文件用 `git restore --source=HEAD --worktree -- _build` 全部拿回（bank/template/脚本无损，重建 md5 仍一致）。
  - 未恢复：`_build/gradle-home`(491M)、`_build/jdk21`(323M)、`_build/study_pdf`(4 份 PDF)、`_build/cp`、`_build/shots`。
    gradle/jdk 可按 app-mobile/README 重新下载；study_pdf 可由 `一、学习资料` 里对应 .doc 用 `_build/doc2pdf.ps1`（Word COM）重转。
  - **结论：在含大量未跟踪产物的目录里跑 filter-branch/重写历史前，先把未跟踪目录备份或移出。**
